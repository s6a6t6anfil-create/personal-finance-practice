# Особисті фінанси — частина 3
React 19, React Router 7, Vite 7, SCSS. Клієнт до API server/ частини2; суми у гривнях передаються цілими копійками.

## Спільний запуск
Потрібен Node.js22+; перевірено Node25.2.1/macOS.
У першому терміналі з кореня репозиторію:
```sh
cd server
npm ci
cp .env.example .env
npm run migrate
npm start
```
У другому:
```sh
cd client
npm ci
npm run dev
```
Відкрити http://127.0.0.1:5173/. API — http://127.0.0.1:3072/, Swagger — http://127.0.0.1:3072/docs/.
Vite проксі /api на сервер. client/.env.example описує VITE_API_URL для іншої адреси; для прямого підключення узгодити server CORS_ORIGIN з адресою клієнта. npm run build створює dist; npm run preview дає лише прев'ю, для API потрібне налаштування VITE_API_URL/CORS (проксі dev не переноситься у production).

## Використання
Спочатку додайте категорію; потім доходи/витрати та місячний бюджет. Кнопка Змінити відкриває форму PUT, Видалити — підтвердження. Огляд показує доходи, витрати, заощадження, їх частку, бюджет та залишок. Категорію з пов'язаними даними видаляти не можна. Один бюджет для категорії та місяця. Обраний місяць зберігається у localStorage; фінансові записи — тільки SQLite сервера.

## Архітектура
ServicesProvider ін'єктує FinanceApi і Preferences; сторінки Dashboard/ResourcePage керують завантаженням та станом. 8 повторно використовуваних компонентів у components/ з власними SCSS у styles/components/. HashRouter: /, /transactions, /budgets, /categories та404. Native Fetch обробляє HTTP, мережеві помилки, 204 і некоректний JSON. SCSS має змінні, міксини, вкладеність; вузькі екрани — одна колонка.

## Перевірки
```sh
npm test
npm run build
cd ../server
npm test
```
4 клієнтські unit та25 API-тестів успішні. У браузері перевірено CRUD усіх3ресурсів, скасування delete, конфлікти, суми, дату, аналітику, localStorage/reload, loading/error/retry,404 та вузький екран. Реальні телефони та Safari/Firefox окремо не перевірялися. API не змінився, Swagger збережений.

## Межі
Локальний навчальний прототип: один користувач, UAH, без авторизації, банківських інтеграцій та синхронізації. Повний аудит доступності/клавіатури й навантаження не проводився. У server/ залишаються10 відомих попередніх залежнісних попереджень audit; client audit0. Перед використанням з реальними фінансами потрібні захист, виправлення залежностей і резервне копіювання. Початковий CLI — окрема база, автоматична міграція даних не реалізована.
